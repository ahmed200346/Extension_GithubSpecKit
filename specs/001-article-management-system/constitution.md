# Gestion d'Articles à Vendre Constitution

## Core Principles

### Best Practices & Standards
The project MUST strictly adhere to the best practices of each language and framework used. This includes PEP 8 for Python, semantic HTML5, modern CSS (Flexbox/Grid), and clean, modular JavaScript. Rationale: Ensures professional code quality, interoperability, and ease of collaboration.

### User-Centric Dynamic Interface
The frontend MUST provide a dynamic and responsive experience using JavaScript to enhance interactivity without compromising accessibility or SEO. Rationale: A modern e-commerce experience requires a seamless, fast, and adaptive user interface.

### Maintainability & Readability
Code MUST be modular and well-documented. Python logic SHOULD be separated from presentation layers (e.g., following an MVC pattern) to ensure the project is easy to maintain and scale. Rationale: Reduces technical debt and simplifies the onboarding of new contributors or future refactoring.

### Robust Validation
All inputs, both at the frontend and backend levels, MUST be validated. Data integrity for article management is non-negotiable to prevent operational errors and security vulnerabilities. Rationale: Prevents corrupted data and protects the system from malicious input.

### Simplicity & YAGNI
Avoid over-engineering. Features SHOULD be implemented based on actual needs. Start with a clean, minimal implementation and expand iteratively. Rationale: Prevents wasted effort on unused features and keeps the codebase lean.

## Technology Stack
The project is built using:
- **Backend**: Python (Framework to be specified during planning, e.g., Flask or Django)
- **Frontend**: HTML5, CSS3, JavaScript
- **Storage**: A structured database for article management (e.g., SQLite for MVP)

## Development Workflow
The development process follows these gates:
1. **Iterative Cycle**: Concept → Specification → Implementation → Validation.
2. **Version Control**: All changes MUST be tracked via Git.
3. **Compliance Review**: Each feature implementation MUST be audited against the Core Principles before being considered complete.

## Governance
The Constitution is the highest authority for project standards and supersedes all other informal practices. Any amendments to the Core Principles MUST be documented, approved, and versioned. Compliance is verified during the review phase of every feature.
